기업의 안전한 AI 활용, 보안성 검토는 어디서 시작해야 할까?

사용 현황부터 데이터 흐름과 개발 결과물까지, AI 보안성 검토의 시작

2026년 9월 18일10m

핵심 세 가지

  • 사내에 구축한 AI도 내부정보 노출과 접근 권한 문제를 점검해야 합니다.
  • AI 활용 기준과 관리 책임은 사용 부서·개발·운영·보안 조직이 함께 정해야 합니다.
  • OWASP의 주요 위협을 기업 환경에 맞는 구체적인 점검 항목으로 바꿔 활용해야 합니다.

기업에서 AI를 활용하는 일은 이미 일상적인 업무의 일부가 되었습니다. 문서 작성과 자료 요약은 물론, 프로그램 개발과 홈페이지 제작, 프로젝트 관리와 업무 자동화까지 AI의 활용 범위가 넓어지고 있습니다. 직원이 외부 AI 서비스를 이용하기도 하고, 기업이 자체 환경에 AI 모델을 구축해 사내 문서와 업무 시스템을 연결하기도 합니다.

이러한 변화는 업무의 속도와 편의성을 높여줍니다. 동시에 기업이 살펴봐야 할 정보의 이동 경로와 접근 권한도 늘어납니다. 개발을 위해 제공한 소스코드, 분석을 위해 연결한 업무 데이터, 답변의 근거로 검색한 내부 문서가 AI를 사용하는 과정에서 어떻게 처리되는지 확인해야 합니다.

취약점 진단 업무를 하면서 제가 고민하는 부분도 여기에 있습니다. 활용 속도가 빨라질수록 정보와 권한이 어디까지 연결되는지 함께 확인해야 합니다. 제가 속한 취약점 진단팀에서 보안성 검토에 LLM 점검을 포함하는 이유도 이러한 위험을 줄이고 예방하기 위해서입니다. (실제로 25년도에서 26년도 현재 그 차이가 많이납니다..AI활용이든 LLM이 포함된 시스템이든..)

이 글에서는 기술적인 기법에 앞서, 기업이 AI 활용 범위와 책임을 정하고 보안성 검토로 연결하는 방법을 살펴보겠습니다.

① AI 사용 현황과 정보의 흐름을 확인합니다

기업에서는 우선 현재 AI가 사용되는 업무와 서비스를 파악하는 것부터 시작할 수 있습니다. 직원이 사용하는 외부 서비스, 개발 도구에 포함된 AI 기능, 사내 문서 검색 서비스, 업무 시스템과 연결된 자동화 기능을 확인하고 각각의 사용 목적과 담당자를 정리하는 것입니다. 이미 운영 중인 AI도 이 과정에 포함해야 합니다.

외부 AI를 사용할 때는 내부정보가 공급자에게 전달되는 경로와 처리 조건을 확인해야 합니다. 자체 구축 환경에서는 기업이 직접 통제할 수 있는 범위가 넓어지지만, 연결된 데이터와 사용자 권한을 관리할 책임도 함께 커집니다.

다음으로는 정보가 처리되는 전체 경로를 확인해야 합니다. 사용자가 직접 입력하는 질문뿐 아니라 첨부파일, 자동으로 검색되는 문서, 연결 시스템에서 가져오는 데이터, 생성된 답변과 운영 로그까지 살펴봐야 합니다. 외부 공급자의 모델 학습에 사용되는지, 어느 위치에 얼마나 보관되는지, 누가 접근할 수 있는지는 각각 확인해야 할 사항입니다.

그림 1. 입력·처리·답변과 실행의 경로마다 정보와 권한을 확인합니다.

예를 들어 사내 문서 검색 AI가 있다고 가정해보겠습니다. 일반 직원의 질문에 인사 담당자만 볼 수 있는 문서가 포함된다면, 정보가 회사 밖으로 나가지 않았더라도 문제가 됩니다. 검색 과정에서 직원의 접근 권한이 제대로 적용되지 않은 것입니다. 모델이 사내에 있다는 사실만으로 이런 위험이 해결되지는 않습니다.

AI를 활용한 개발 결과물도 관리 범위에 포함해야 합니다. AI로 만든 홈페이지나 자동화 프로그램에도 인증, 접근 권한, 비밀정보 관리, 사용한 라이브러리 등에 대한 보안 검토가 필요합니다. 기업은 생성된 코드를 누가 검토하고, 어떤 절차를 거쳐 운영 환경에 반영할지 정해야 합니다. 해당 서비스에 LLM 기능까지 탑재된다면 그에 따른 보안 위험을 추가로 검토해야 합니다.

② 사용 기준과 관리 책임을 정합니다

정보보호 관점의 AI 거버넌스는 어떤 목적으로 AI를 사용하고, 어떤 정보와 권한을 허용하며, 그 결정을 누가 책임질지 정하는 일입니다. 정한 기준을 개발·도입·운영 절차에 적용해야 효과가 있습니다.

보안성 검토를 준비할 때는 서비스별로 다음 내용을 정리하고, 실제 설정과 기록을 확인합니다. 예를 들어 사내 문서 검색 AI라면 검색 대상 문서, 접근 가능한 사용자, 질문·답변 로그의 보관 위치와 기간을 확인하는 것입니다. 아래 질문으로 서비스별 검토 내용을 정리할 수 있습니다.

검토 관점 기업이 확인해야 할 질문
사용 목적과 관리 대상 어떤 업무에 AI를 사용하며, 해당 서비스와 업무의 책임자는 누구인가?
정보의 처리와 보관 어떤 정보를 입력·검색·생성하며, 어디로 전송하고 얼마나 보관하는가?
접근 권한과 작업 범위 사용자별 정보 접근 권한이 적용되는가? 조회·수정·삭제·외부 전송 중 어디까지 허용하는가?
공급자와 개발 결과물 외부 서비스·모델·연결 도구의 보안 조건을 확인했는가? AI가 생성한 코드의 검토 책임과 절차가 있는가?
승인과 위험 수용 중요한 작업에 사람의 승인이 필요한가? 발견된 문제와 남아 있는 위험은 누가 판단하는가?
운영과 사고 대응 이상 동작을 확인할 수 있는가? 필요할 때 기능을 중단하고 권한을 회수하거나 데이터를 복구할 수 있는가?

업무 부서는 활용 목적과 업무 영향을 설명하고, 개발·운영 부서는 필요한 통제를 구현하며, 보안 부서는 위험과 통제의 적절성을 검토하는 식으로 역할을 나눌 수 있습니다. 점검 후 남은 위험을 누가 수용할지, 어떤 조건에서 사용 범위를 제한할지도 정해야 합니다.

직원에게 적용되는 기준 역시 실제 사용 가능한 형태여야 합니다. 사용할 수 있는 도구, 입력 가능한 정보, 예외 신청 경로를 알려주면 구성원이 업무 과정에서 기준을 적용하기 쉬워집니다.

③ 보안성 검토로 기준의 실제 작동을 확인합니다

보안성 검토에서는 정책과 설계가 실제 시스템에 적용되었는지 확인합니다. “권한에 따라 문서를 제공한다”는 기준이 있다면, 권한이 다른 테스트 계정으로 같은 질문을 했을 때 검색 결과와 답변이 적절히 제한되는지 점검해야 합니다. “발송 전 승인”이 기준이라면 승인 없이 실행되는 경로가 없는지 확인해야 합니다.

그림 2. 설계·오픈 전·운영 단계에 적용하는 보안성 검토 흐름의 예시입니다.

모델이나 검색 데이터가 바뀌거나 외부 도구와 새 권한이 추가되면 기존 검토가 어디까지 유효한지 확인해야 합니다. NCSC도 운영 단계의 로깅·모니터링과 업데이트 관리를 다루며, 변경 과정에서 시스템을 시험하고 평가하도록 권고합니다. NCSC 운영·유지보수 지침

④ 공개된 위협을 우리 회사의 점검 질문으로 바꿉니다

OWASP LLM Top 10은 LLM 애플리케이션의 주요 보안 위험을 이해하는 데 활용할 수 있습니다. 도구를 이용해 업무를 수행하는 AI에는 Agentic Applications 관련 자료도 참고할 수 있습니다. OWASP LLM Top 10 · OWASP Agentic Top 10

이러한 자료를 기업 환경에 적용할 때는 각 위험을 구체적인 질문으로 바꾸는 과정이 필요합니다. “민감정보 노출”이라는 항목을 사내 문서 검색 AI에 적용한다면, “요청한 직원에게 허용되지 않은 문서가 검색되거나 답변에 포함되는가?”처럼 점검 대상을 명확히 하는 것입니다. 항목을 확인했다는 사실만으로 시스템 전체의 안전을 보장할 수는 없습니다.

우선 현재 사용 중이거나 도입을 준비하는 AI 하나를 골라, 정보의 흐름과 권한, 관리 책임자를 정리해보면 좋겠습니다. 확인되지 않은 데이터 경로나 책임이 불분명한 기능이 있다면, 그 지점부터 보안성 검토를 시작할 수 있습니다.

방문 통계
같은 브라우저의 방문을 한국 시간 기준 하루 한 번 집계합니다. 무작위 식별자를 브라우저에 저장하고 서버에는 해시한 중복 확인값을 보관합니다. 지난 날짜의 확인값은 자정 이후 정리하며, 집계 수치는 유지합니다. IP 주소와 방문 페이지는 집계 저장소에 보관하지 않습니다.

사이트 보안과 외부 서비스
과도한 요청을 제한하기 위해 IP 주소를 사용합니다. Cloudflare·GitHub도 사이트 제공과 보안을 위해 접속 정보를 처리할 수 있으며, Turnstile은 IP·브라우저 정보를 봇 차단과 탐지 기능 개선에 이용합니다. 외부 서비스에서 정보가 국외 처리될 수 있고, 보관에는 각 업체의 정책이 적용됩니다.
Cloudflare Turnstile · Cloudflare · GitHub

브라우저 저장정보
방문 식별자는 다른 날짜에 재방문하면 교체하고, 화면 모드 설정은 브라우저에 유지합니다. 브라우저의 ‘쿠키 및 사이트 데이터’ 설정에서 삭제하거나 저장을 제한할 수 있습니다. 제한하면 방문 집계와 화면 설정 저장이 작동하지 않을 수 있습니다.
