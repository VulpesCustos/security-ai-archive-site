.arpa 도메인을 악용한 피싱: 역방향 DNS 이름이 웹 링크로 사용된 사례

ip6.arpa 하위 이름을 웹 링크로 악용한 공개 사례를 살펴보고, 정상적인 역방향 DNS 조회와 구분하기 위한 점검 기준을 정리합니다.

2026년 9월 7일5m

핵심 요약

  • .arpa는 인터넷 인프라용 최상위 도메인이며, 대표적인 용도 중 하나는 IP 주소의 역방향 DNS 조회다.
  • Infoblox가 공개한 피싱 사례에서는 메일 이미지에 연결된 URL의 호스트로 ip6.arpa 하위 이름이 사용됐다.
  • 탐지 시에는 DNS 질의 유형, 메일의 실제 URL, 관련 웹 통신을 함께 확인해야 한다. .arpa 이름이 관찰됐다는 사실만으로 악성이라고 판단해서는 안 된다.

배경: .arpa 도메인은 무엇인가?

.arpa는 Address and Routing Parameter Area의 약자로, 인터넷 인프라를 지원하기 위해 지정된 최상위 도메인이다. IANA가 IAB의 지침 아래 관리하며, 대표적인 하위 도메인의 용도는 다음과 같다.

도메인 목적
in-addr.arpa IPv4 주소를 도메인 이름으로 매핑
ip6.arpa IPv6 주소를 도메인 이름으로 매핑

일반적인 정방향 DNS 조회는 도메인 이름에 대응하는 IP 주소를 찾는다. 반대로 역방향 DNS 조회는 IP 주소에 대응하는 이름을 찾으며, 이때 주로 PTR 레코드를 사용한다.

예를 들어 IPv4 주소 192.0.2.10의 역방향 조회 이름은 다음과 같다.

10.2.0.192.in-addr.arpa

IPv6 주소 하나의 역방향 조회 이름을 만들 때는 생략된 0을 복원한 뒤, 16진수 한 자리씩 역순으로 나열하고 각 자리 사이에 점을 넣은 다음 ip6.arpa를 붙인다. 이때 한 자리는 4비트인 니블(nibble)에 해당한다.

이러한 정상적인 용도가 있으므로, DNS 로그에서 .arpa 이름이 관찰됐다는 사실만으로 악성이라고 판단할 수는 없다.

공개 사례에서 확인된 악용 방식

Infoblox는 2026년 2월 26일, .arpa를 악용한 피싱 캠페인을 공개했다. 보고서는 공격자가 IPv6 주소 대역에 대응하는 역방향 DNS 영역의 관리 권한을 확보하고, 해당 영역에 A 레코드를 설정하는 데 Hurricane Electric과 Cloudflare를 악용한 사례를 설명한다. 이는 보고 당시 관찰된 동작이며, 현재 모든 DNS 제공업체에서 같은 구성이 가능하다는 의미는 아니다.

A 레코드는 도메인 이름을 IPv4 주소에 연결한다. 이 사례의 핵심은 PTR 레코드나 역방향 조회 기능 자체가 웹 링크로 바뀐 것이 아니라, 역방향 DNS용 이름이 A 레코드를 통해 웹 URL의 호스트로 사용됐다는 점이다.

단계 Infoblox가 보고한 내용
메일 유입 유명 브랜드를 사칭하고 경품·설문 등을 내세워 이미지 클릭 유도
최초 링크 이미지에 연결된 URL의 호스트로 ip6.arpa 하위 이름 사용
주소 해석 해당 이름의 A 레코드가 웹 접속용 IPv4 주소 반환
접속자 선별 트래픽 분배 시스템(TDS)이 접속 환경을 확인하고 리디렉션
최종 유도 조건에 맞는 접속자에게 배송비 등의 명목으로 카드 정보 입력 유도

공개 사례의 공격 구성 흐름

다음은 Infoblox의 공개 분석을 기준으로 정리한 흐름이다.

  1. IPv6 주소 대역과 해당 역방향 DNS 영역의 관리 권한을 확보한다.
  2. DNS 제공업체에서 해당 영역을 관리하도록 구성하고, 웹 접속 주소를 반환하는 A 레코드를 설정한다.
  3. ip6.arpa 하위 이름을 호스트로 사용하는 URL을 메일 이미지에 연결해 피싱에 이용한다.

이 과정에서 IPv6 터널링 서비스는 주소 대역과 관리 권한을 얻는 수단이었다. 피해자의 웹 통신이 그 터널을 통과해야 하는 것은 아니며, A 레코드가 반환한 IPv4 주소로 접속할 수 있다. 보고서에는 위임받은 영역에 무작위 하위 이름을 덧붙인 사례도 나온다. 따라서 공격 URL의 호스트가 항상 IPv6 주소 하나를 그대로 역순으로 표현한 이름인 것은 아니다.

탐지 및 대응 방안

아래는 이 사례를 바탕으로 정리한 권장 점검 항목이다. 각 항목을 단독 악성 판정 기준으로 사용하기보다는, 메일·DNS·웹 기록의 시각과 발생 주체를 연결해 확인하는 것이 좋다.

표는 좌우로 움직여 볼 수 있습니다.

확인 대상 확인할 내용 판단 시 고려할 점
메일 원문 이미지에 연결된 실제 URL과 호스트 이름 화면에 표시된 브랜드나 이미지와 실제 목적지를 구분한다.
DNS 기록 질의 이름·유형, 응답 IP, 발생 시각, 질의한 장비 정상 PTR 조회와 웹 주소 해석을 위한 A·AAAA 조회를 구분한다. 이 보고서에서 관찰된 악용은 A 레코드다.
웹·프록시 기록 실제 접속 여부, 리디렉션 경로, 최종 목적지 DNS 조회만으로 피싱 페이지 접속이나 정보 입력을 단정하지 않는다.
사용자·보안 장비 기록 사용자 클릭 기록, 메일 보안 제품의 URL 검사 기록 같은 URL에 대한 접속이라도 사용자 행동인지 자동 검사인지 구분한다.
대응 범위 악성 근거가 확인된 URL·호스트, 정상 이용과 예외, 업무 영향 .arpa 전체에 대한 일괄 차단보다 확인된 대상과 통제 지점을 기준으로 조치를 검토한다.

메일 보안 장비는 메일 처리 과정이나 클릭 시점에 URL을 검사할 수 있다. 따라서 관련 DNS 질의나 웹 접속 기록이 존재한다는 이유만으로 사용자가 직접 링크를 클릭했다고 판단해서는 안 된다. 사용자와 보안 장비의 기록을 대조해 해석해야 한다.

.arpa 전체의 DNS 조회를 일괄 차단하면 정상적인 역방향 조회와 다른 인프라 기능에도 영향을 줄 수 있다. 메일 URL과 웹 접속에서 의심스러운 사용을 식별하고, 악성 근거가 확인된 대상에 대해 격리·접속 제한을 검토하는 접근이 적절하다.

마무리

운영 관점에서는 “어떤 도메인인가”와 “그 도메인이 무엇을 하고 있는가”를 함께 판단할 필요가 있다. 인프라용 이름이라는 이유만으로 웹 링크를 신뢰해서는 안 되며, 정상적인 역방향 조회까지 악성으로 취급해서도 안 된다.

또한 .arpa를 사용하면 모든 보안 제품을 우회한다는 식의 일반화는 피해야 한다. 탐지 여부는 제품의 URL 분석 기능, DNS 가시성, 실제 적용 정책에 따라 달라진다. 이 글의 점검 항목을 조직 환경에 맞게 검증하고, 확인 가능한 근거를 바탕으로 대응 범위를 정하는 것이 중요하다.
